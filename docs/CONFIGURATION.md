# Configuration & Deployment Guide

This document specifies all configurable parameters, environment variables, security best practices, and production infrastructure guidelines for the **HR Lifecycle Integration Service**.

---

## 1. Environment Variables Reference

The service reads configuration from environment variables or a local `.env` file via `pydantic-settings`.

| Variable | Type | Default | Description | Required in Production |
| :--- | :--- | :--- | :--- | :---: |
| `MONGODB_URI` | `string` | `mongodb://localhost:27017/hrdb` | Full MongoDB connection string URI. | **Yes** |
| `MONGODB_DB_NAME` | `string` | `hrdb` | Name of the database for HR data. | No |
| `APP_ENV` | `string` | `development` | Deployment environment: `development`, `staging`, `production`. | No |
| `APP_PORT` | `integer` | `8000` | Port on which FastAPI / Uvicorn binds. | No |
| `LOG_LEVEL` | `string` | `INFO` | Python logging level (`DEBUG`, `INFO`, `WARNING`, `ERROR`). | No |
| `CORRELATION_ID_HEADER` | `string` | `X-Correlation-ID` | HTTP header name for request correlation tracing. | No |
| `JWT_SECRET_KEY` | `string` | *(default dev key)* | Cryptographic key used to sign and verify HS256 JWT tokens. | **Yes** |
| `JWT_ALGORITHM` | `string` | `HS256` | JWT signing algorithm. | No |
| `JWT_EXPIRE_MINUTES` | `integer` | `60` | Token expiration lifetime in minutes. | No |
| `WEBHOOK_HMAC_SECRET` | `string` | *(default dev key)* | Shared secret key for generating `X-Signature-SHA256` headers. | **Yes** |
| `OUTBOX_POLL_INTERVAL_SECONDS` | `integer` | `5` | Frequency of background outbox polling loop in seconds. | No |
| `OUTBOX_MAX_RETRIES` | `integer` | `5` | Maximum delivery attempts before moving outbox items to DLQ. | No |
| `OUTBOX_BACKOFF_BASE_SECONDS` | `integer` | `2` | Base delay for exponential backoff algorithm. | No |
| `OUTBOX_BACKOFF_MAX_SECONDS` | `integer` | `60` | Cap on maximum retry delay between delivery attempts. | No |
| `WEBHOOK_REQUEST_TIMEOUT_SECONDS` | `integer` | `10` | HTTP client timeout for downstream webhook POST requests. | No |
| `MOCK_DOWNSTREAM_URL` | `string` | `http://mock_downstream:9000` | Base URL of the mock downstream service. | No |
| `MOCK_FAILURE_RATE` | `float` | `0.3` | Mock downstream synthetic failure probability (0.0 to 1.0). | No |
| `SEED_EMPLOYEE_COUNT` | `integer` | `50` | Number of synthetic employees generated by `seed.py`. | No |
| `SEED_RANDOM_SEED` | `integer` | `42` | Deterministic seed for Faker generator reproducibility. | No |

## 2. Production Deployment Guidelines

### 2.1 MongoDB Cluster & Replica Set Requirement
> [!IMPORTANT]
> The Transactional Outbox pattern requires **MongoDB multi-document ACID transactions**. MongoDB supports transactions **only** on replica sets or sharded clusters (standalone single-instance nodes without a replica set will reject session transactions).

- **MongoDB Atlas**: Fully supported by default. Supply your Atlas SRV connection string:
  ```env
  MONGODB_URI=mongodb+srv://app_user:StrongPassword@cluster0.abcde.mongodb.net/hrdb?retryWrites=true&w=majority
  ```
- **Self-Hosted MongoDB**: Initialize the replica set using `rs.initiate()` before starting the API service.

### 2.2 Security Hardening
1. **Secrets Management**: Store `JWT_SECRET_KEY` and `WEBHOOK_HMAC_SECRET` in a secure secrets store (AWS Secrets Manager, HashiCorp Vault, Azure Key Vault, or Kubernetes Secrets).
2. **TLS / HTTPS**: Terminate TLS at the ingress reverse proxy (NGINX, Traefik, or AWS ALB). Enforce HTTPS redirect for all incoming traffic.
3. **Database Whitelisting**: Restrict MongoDB access exclusively to the private CIDR block of the application container cluster.
4. **Non-Root Execution**: Both production and mock Dockerfiles create and drop privileges to a dedicated non-root `appuser`.

### 2.3 Resource Sizing & Container Limits

Recommended container resource allocations for high-availability production workloads:

| Service Component | Replicas | CPU Request / Limit | Memory Request / Limit |
| :--- | :--- | :--- | :--- |
| **API Web Service** | 2–4 | 250m / 1000m | 512 MiB / 1 GiB |
| **Outbox Worker** | 1–2 | 250m / 500m | 256 MiB / 512 MiB |
| **MongoDB (Atlas M10+)**| 3 nodes (ReplSet) | Dedicated | 2 GB+ RAM |

### 2.4 Monitoring & Observability
- **Health Checks**: Configure Kubernetes liveness probe against `/health` (checks process status) and readiness probe against `/ready` (verifies live database ping).
- **Structured Logs**: Configure log aggregation (Datadog, ElasticSearch, AWS CloudWatch) to extract JSON attributes (`correlation_id`, `method`, `duration_ms`, `status`).
- **DLQ Alerting**: Set a metric threshold alert when `status=dead_letter` outbox count exceeds 0.
